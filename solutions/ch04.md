### *P4.1

BFS from 0 reaches distance 4 at vertex 6 (0–1–4–5–6). BFS from 6 reaches distance 6 at vertex 9. The diameter is **6 edges**, for example **9–8–0–1–4–5–6**. *Verified* against BFS from every vertex (`diameter`).

### *P4.2

There are **6 islands**: the 2 × 2 block at the top left; the group {(0, 4), (1, 4), (1, 5)}; the single cells (2, 2), (4, 0) and (4, 2); and {(3, 3), (3, 4), (3, 5), (4, 5)}.

*BFS:* scan the grid; at each unvisited 1, increment the count and flood-fill its island, marking cells as visited when they are *pushed* (`islands`). O(R·C). *Union–find:* for each 1, unite it with the 1s to its right and below; the number of islands is (number of 1s) − (number of successful unions), because each successful union merges two components into one. The program computes both. The DSU version is the better fit when cells are added one at a time ("number of islands after each addition", LeetCode 305), because BFS would have to start over after each change.

### *P4.3

In-degrees: 0 ← {1, 3}, 2 ← {0, 4}, 4 ← {1}, 5 ← {2}; vertices 1 and 3 have in-degree 0. With a min-heap: take 1 (now 4 is ready; 0 still waits for 3), take 3 (0 is ready), take 0, take 4 (2 is ready), take 2, take 5. Order: **1 3 0 4 2 5**. *Verified* against the first valid permutation in lexicographic order (`topo`).

Adding 5→1 creates the cycle 1 → 4 → 2 → 5 → 1. Now only 3 has in-degree 0; after taking it, vertex 0 still waits for 1, and no vertex on the cycle ever reaches in-degree 0. Kahn's algorithm outputs 1 vertex instead of 6, and **any output shorter than n proves a cycle exists**. The vertices not output are those on a cycle or downstream of one.

### *P4.4

(a) f[a] = 1 + min over coins c ≤ a of f[a − c] gives **2 coins** (5 + 6). Greedy takes 9, then 1, then 1: **3 coins**. {1, 5, 6, 9} is not a canonical coin system, so greedy fails (Section 3.9).

### *P4.6

**Edit distance("sunday", "saturday") = 3**: insert 'a' and 't' after the 's', and replace 'n' with 'r'. **LCS("ABCBDAB", "BDCABA") = 4** (for example "BCBA" or "BDAB"). *Verified* (`edit`, `lcs`).

Memory: for the numbers only, two rows of the table suffice (row i depends only on row i − 1), so O(min(n, m)) if the shorter string indexes the columns. ### *P4.8

### *P4.9

Let P be the sum of the elements given '+' and S the total. Then P − (S − P) = target, so **P = (S + target)/2**, which must be a non-negative integer; otherwise the answer is 0. The question becomes "how many subsets sum to P?", a 0/1 counting knapsack with the capacity loop running downwards (`target_sum`).

For [1, 1, 1, 1, 1] and target 3: S = 5, P = 4: choose which four of the five 1s get '+': **5 ways**. For [1, 2, 3, 4, 5] and target 3: S = 15, P = 9, and the subsets with sum 9 are {4, 5}, {2, 3, 4}, {1, 3, 5}: **3 ways**. *Verified* against all 2^{n} sign assignments on random inputs that include zeros. A zero can take either sign, which doubles the count; the DP handles this without a special case, because for x = 0 the update f[s] += f[s − 0] doubles every entry.

### *P4.10

Scan from right to left; for each element, add the number of already-seen (that is, later) elements that are strictly smaller, then insert it. With a Fenwick tree over values this is O(n log n) (`inversions`). The array has **27 inversions**. *Verified* by the O(n^{2}) count.

If values repeat, query the prefix strictly below the value's rank so that equal pairs are not counted (an inversion requires a_{i} > a_{j}). If values are as large as 10^{9}, compress them to ranks 0..n−1 first (sort, `unique`, `lower_bound`; Section 3.3). Merge sort counts inversions in the same O(n log n) without compression and is the other standard answer.

### *P4.11

π("abacabab") = **[0, 0, 1, 0, 1, 2, 3, 2]**. For example π[6] = 3 because "abacaba" has the border "aba"; π[7] = 2 because "abacabab" ends with "ab" but not with "abab".

**HTHT:** π = [0, 0, 1, 2], so the borders are 4 (the whole pattern) and 2 ("HT"); then π[1] = 0 ends the chain. E = 2^{4} + 2^{2} = **20**. **HHTT:** π = [0, 1, 0, 0], so the only border is the whole pattern: E = 2^{4} = **16**. *Verified* by `expected_flips` and by 200,000 simulated runs of each.

Both patterns occur at the same long-run rate, but HTHT overlaps itself, so its occurrences come in clusters; with the same average spacing, clustered occurrences mean a longer wait for the first one (the same argument as P2.8).

### *P4.13

**168,856,464,709,124,010.** Digit DP (`no_adjacent_equal`): numbers shorter than N have 9 choices for the first digit (1–9) and 9 for each later digit (anything except the previous digit), giving 9^{L} numbers of length L. For numbers with N's length, walk N's digits; at position i, every digit d below N's digit that differs from N's previous digit (and is non-zero at position 0) leaves the remaining L − 1 − i positions free, contributing 9^{L−1−i}. If N's own prefix already has two equal adjacent digits, stop: no further number with that prefix is valid. Add 1 if N itself is valid.

For N = 10^{18}, N itself is invalid (its zeros are adjacent), and every valid number has at most 18 digits, so the answer is Σ_{L=1}^{18} 9^{L} = (9^{19} − 9)/8, which matches. *Verified* also against brute force for every N up to 20,000.

### *P4.14

**130.** *Verified* against brute force over all 5! burst orders (`burst`).

Why "last": if k is the *first* balloon burst in an interval, its neighbours at that moment are known, but afterwards its left and right neighbours become adjacent, so the two sides are no longer independent subproblems. If k is the *last* balloon burst in the open interval (l, r), then every other balloon in (l, k) is burst while k is still present, so that side's neighbours are bounded by l and k regardless of what happens on the other side, and likewise for (k, r). At the moment k bursts, only l and r remain as its neighbours, so it earns a_{l}·a_{k}·a_{r}. Hence f(l, r) = max_{k} f(l, k) + a_{l}a_{k}a_{r} + f(k, r), over intervals in increasing length: O(n^{3}).
