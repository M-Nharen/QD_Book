## Chapter 8: Modern C++

### *P8.1

(a) **lvalue**: a named variable, whatever its declared type. (b) **lvalue**: `std::move(v)` is an xvalue, but `std::vector::operator[]` is not ref-qualified and returns `int&` for any object expression, so the result is an lvalue. (c) **lvalue**: a call to a function returning an lvalue reference. (d) **prvalue**: `operator+` returns `std::string` by value. (e) **lvalue**: `p->id` is `(*p).id`, and `*p` is an lvalue. (f) **xvalue**: a member of an xvalue. (g) **prvalue**: a literal. (h) **lvalue**: built-in assignment returns its left operand. (i) **xvalue**: subscripting an *array* rvalue (built-in `[]` on an xvalue array) gives an xvalue element, unlike the vector case in (b). *Verified* with the `decltype((e))` classifier of Listing 8.1.

### *P8.2

| Statement | Copies | Moves | Why |
|---|---|---|---|
| (a) `push_back(t)` | **1** | 0 | `push_back(const T&)` copy-constructs the element |
| (b) `push_back(std::move(t))` | 0 | **1** | `push_back(T&&)` move-constructs it |
| (c) `push_back(T{"y"})` | 0 | **1** | the prvalue is materialized to bind to `T&&`, then moved into the element |
| (d) `emplace_back("z")` | 0 | 0 | the element is constructed directly from `const char*` |
| (e) `emplace_back(u)` | **1** | 0 | forwards an lvalue: the copy constructor runs in place |

No reallocation happens because of `reserve(10)`. *Verified.*

### *P8.3

| Body | Copies | Moves | Guaranteed by the language? |
|---|---|---|---|
| (a) `return T{"a"};` | 0 | 0 | **yes** (prvalue, C++17) |
| (b) `T t; return t;` | 0 | 0 | no: NRVO is permitted; if not done, it must be a move |
| (c) `return std::move(t);` | 0 | **1** | yes: not a name, so no NRVO; a move |
| (d) `return p;` (by-value parameter) | 0 | **1** | yes: parameters are never elided; implicit move |
| (e) `return m;` (data member) | **1** | 0 | yes: not a local, so a copy |
| (f) `return c ? a : b;` | **1** | 0 | yes: an lvalue expression, not a name |
| (g) `const T t; return t;` | 0 | 0 | no: NRVO applies to const locals too; but if not elided, it would be a **copy**, because a const object cannot be moved from |

Case (g) is why returning a `const` local is a bad habit: correct code today, a silent copy on a compiler or in a function shape where NRVO does not apply. *Verified* with GCC 13 at `-O2`.

### *P8.4

| Call | Argument | `U` | type of `x` |
|---|---|---|---|
| (a) `f(i)` | lvalue `int` | `int&` | `int&` |
| (b) `f(ci)` | lvalue `const int` | `const int&` | `const int&` |
| (c) `f(5)` | prvalue `int` | `int` | `int&&` |
| (d) `f(std::move(ci))` | xvalue `const int` | `const int` | `const int&&` |
| (e) `f(ri)` | lvalue `int` (a reference names its referent) | `int&` | `int&` |

In (d), `std::move(x)` yields `const int&&`. It cannot bind to `int&&` (that would drop `const`), so overload resolution picks `const int&`: the "move" becomes a copy, the same effect as Listing 8.2, lines 61–65. *Verified* with `static_assert`s.

### *P8.5

Every `push_back(T{...})` moves the temporary into place: **1000 moves**. In addition, reallocations happen when the size reaches 1, 2, 4, …, 512 (capacity grows to 1, 2, 4, …, 1024), and each relocates all current elements: 1 + 2 + 4 + … + 512 = 2^{10} − 1 = 1023 relocations.

(a) `noexcept` move: relocations are moves. **0 copies, 1000 + 1023 = 2023 moves.**

(b) Potentially-throwing move (and a copy constructor available): `std::move_if_noexcept` makes relocations copies. **1023 copies, 1000 moves.** *Verified.* (With `reserve(1000)` up front, both cases would perform exactly 1000 moves and no copies.)

### *P8.6

(a) **Dangling view.** `o.venue + ":" + o.ticker` is a temporary `std::string`; the returned `string_view` points into it, and the temporary is destroyed at the end of the `return` statement. Every use of the result is undefined behaviour (Section 11.4). Fix: return `std::string` (accepting the allocation), or better for the hot path, write into a caller-provided fixed buffer, or keep a pre-built symbol table and return a view into storage that lives as long as the table.

(b) **The "move" is a copy.** A `const` data member cannot be moved from, so the defaulted move constructor copy-constructs `levels`: every "move" of a `Book` allocates and copies the whole vector. Also, a `const` member deletes the copy and move *assignment* operators, so `Book` cannot be assigned or stored in containers that assign. Fix: make the member non-const and protect it with encapsulation (private member, const accessor).

(c) **Dangling reference capture.** `[&]` captures the parameter `s`, a reference, so the closure holds a reference to the `Session` object. Calling the stored closure after that session is destroyed is a use-after-free. Fix: capture something with a well-defined lifetime: a session ID that the callback looks up (and handles "not found"), a `std::weak_ptr<Session>` checked with `lock()`, or remove the callback from the registry in `Session`'s destructor (RAII registration).

(d) **Forwarding twice.** If a caller passes an rvalue, `log` may move from it, and `send` then receives a moved-from object (Listing 8.3, lines 39–43). Fix: pass plain lvalues to every use except the last: `log(a...); send(std::forward<A>(a)...);`. In practice a logging call should take `const&` parameters anyway.

### *P8.8

The traits class separates "what a handle is" from "how ownership works". `release()` hands the handle out and leaves the owner empty; `reset()` swaps in the new handle *before* closing the old one and skips closing when old and new are equal. That ordering is what makes self-move-assignment safe: `reset(o.release())` with `o` being `*this` first empties the object, then re-adopts the same handle without closing it.

### *P8.9

A `FunctionRef` stores a type-erased pointer to the callable (`void*`) and a pointer to a function, instantiated per callable type by the lambda in the constructor (lines 30–33), that casts the `void*` back and invokes it. The constructor is constrained so that it is not chosen as a copy constructor and accepts only callables with a compatible signature.

**Lifetime rule:** a `FunctionRef` must not outlive the callable it refers to. Passing a lambda directly as an argument is safe, because the temporary closure lives until the end of the full expression containing the call. Storing a `FunctionRef` built from a temporary in a member or a container is a dangling reference. That restriction is the price of never allocating; for callbacks that must be stored, use a template parameter, a fixed-capacity inline function, or (off the hot path) `std::function`. C++26 standardizes this design as `std::function_ref`.

### *P8.10

The key points are in the special members. A union member with a non-trivial type has no default constructor or destructor, so the class must construct and destroy the value explicitly (`std::construct_at` and `std::destroy_at`, Section 7.3), and every operation must consider both states of both operands:

- **Copy/move construction:** construct only if the source is engaged.
- **Copy/move assignment:** both engaged, *assign* the value (reusing its resources); only the source engaged, *construct*; source empty, `reset()`.
- **`emplace`:** destroy any old value, construct the new one, and set the flag only after construction succeeded, so a throwing constructor leaves the object correctly empty.
- **Moving from an engaged `Optional`** leaves the source engaged with a moved-from value, as `std::optional` does.

### *P8.11

Three ingredients: perfect forwarding of the callable and the arguments (`F&&`, `Args&&...`, `std::forward`); `std::invoke`, which handles function pointers, lambdas and pointers to member functions uniformly; and a `decltype(auto)` return type, which deduces `int&` for a function returning `int&`, `std::string` for a prvalue (which is then returned with guaranteed elision, because `return std::invoke(...)` is itself a prvalue expression), and `void` for `void`. Measuring with a local RAII object rather than code after the call means the time is recorded on every exit path, including exceptions, and it is also what makes `void` work without a special case (there is no result variable to hold).
